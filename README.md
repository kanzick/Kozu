Android music app for osu! built with Kotlin.

## What news ✨

- **Catalogue provider:** osu! API v2 is primary whenever a valid osu! OAuth token is available. Search, Mix, Explore and All beatmaps request only `ranked` and `loved`, across every game mode. The UI and repository both filter exact status values, so `pending`, `wip`, `graveyard`, `approved` and `qualified` cannot leak into those catalogue results.
- **Guest fallback:** when no official token can be obtained, Kozu uses the public Hinai beatmap index, requesting `ranked` and `loved` separately. The Search screen and All beatmaps page label this as a public fallback. Public mirrors cannot guarantee identical coverage to osu! official and do not include removed/private/unindexed mapsets.
- **Audio sources:** Hinai cached full audio, Sayobot direct audio, osu.direct, Nekoha (via its documented Hinai collaboration redirect), Mirria, osu!dl, Mino/catboy, Sayobot archive and Beatconnect. Nerinyan is omitted to avoid a known cascading/looping source path. Independent sources are raced with one shared ~4.5-second resolution budget, rather than serially waiting on each source. Hinai's cascade can choose a partner URL, but Kozu streams the selected partner directly rather than proxying every archive byte through Hinai.
- **Streaming from `.osz`:** Kozu reads the ZIP central directory using HTTP Range, locates the audio entry and inflates it incrementally through a Media3 `DataSource`. It no longer waits for the complete song to download and unpack before playback can start. A mirror that rejects HTTP Range or returns an invalid ZIP directory is skipped by the low-latency streaming path; there is no guarantee that every mirror can serve every set.
- **Source validation and retry:** Hinai direct audio is used only when metadata says `audio_cached = true`. Sayobot's direct URL is checked for actual audio bytes. ZIP mirrors are checked for valid range responses and a recognized audio entry. If a source fails in Media3, Kozu marks it failed and retries another full-song provider; FULL mode never silently falls back to a short preview.
- **Startup policy:** stream resolution has a shared 4.5-second deadline, with 2-second connect and 4-second read timeouts for the first audio response. Media3 starts with an 800 ms startup buffer and builds a larger buffer while playing. This is an optimization target, not a hard guarantee: server latency, carrier routing, Range support and weak connections can still exceed 10 seconds or leave no viable source. A Range-capable mirror is required for incremental `.osz` streaming; on mirrors without it, Kozu may need a different provider.
- **Cache lifecycle:** Media3 maintains a bounded disk cache while playback is active. Temporary streamed audio and Media3 cache are cleared when the playback service is destroyed; offline downloads are stored separately and are not deleted.
- **Refresh:** Home and Explore have pull-to-refresh feedback, and tapping the Kozu title on Home triggers the same catalogue refresh.
- **Greeting:** Home uses the signed-in osu! username unless a custom Kozu display name is set in Settings.
